WDK CLI beta.5 exposes selected chain-specific wallet methods that do not fit the generic address, balance, history, and send commands. The bundled catalog declares each allowed method, its `read` or `write` kind, and its parameter schema.

## Discover Before Calling

List one network's declared methods:

```bash title="Terminal"
wdk method list --network ethereum
```

Or inspect every built-in module that declares methods:

```bash title="Terminal"
wdk method list --all
```

Provide exactly one of `--network` and `--all`. Listing does not require an unlocked wallet.

The method catalog is an allowlist. `wdk method call` rejects a method or parameter that is not declared; it does not reflect over arbitrary package exports. Beta.5's method catalog covers built-in modules only, even when a custom module backs a custom network.

## Call A Read Method

First inspect the exact schema:

```bash title="Terminal"
wdk method list --network ethereum
```

Then pass one flag for each required parameter:

```bash title="Terminal"
wdk method call \
  --network ethereum \
  --name getAllowance \
  --token 0xTOKEN_ADDRESS \
  --spender 0xSPENDER_ADDRESS \
  --wallet WALLET \
  --index 0
```

The selected wallet must be unlocked because method calls run against a wallet account in the daemon. Use `--wallet <name>` and `--index <n>` when the default selection is not the intended account.

## Format Parameters

| Declared type | CLI value |
| --- | --- |
| `string` | Non-empty string |
| `number` | Finite numeric value |
| `boolean` | Explicit `true` or `false` value |
| `bigint` | Non-negative decimal integer string in base units |
| Scalar array such as `string[]` | Comma-separated values |
| Object or structured array | One JSON string; quote every nested `bigint` as a decimal string |

Camel-case parameter names become kebab-case flags. For example, `maxFeeSats` becomes `--max-fee-sats`. Optional parameters may be omitted, but every flag you provide must have a value, including boolean flags.

Returned `bigint` values become decimal strings in both normal object output and `--json` output.

## Call A Write Method

<Callout type="error">
A method labeled `write` can move funds or mutate on-chain state. The label is discovery metadata, not an authorization control. `wdk method call` has no dry-run, fee-preview requirement, confirmation prompt, or second passphrase check after unlock.
</Callout>

Before calling a write method:

1. Run `wdk method list --network NETWORK` and verify the method is marked `write`.
2. Resolve and display the exact wallet, account index, network, method, and arguments.
3. Use a module-specific quote or read method when the catalog provides one.
4. Ask the user to confirm those exact values.
5. Call the method once, then verify its returned identifier and resulting state.

For example, an EVM approval is a write method and the amount is in token base units:

```bash title="Terminal"
wdk method call \
  --network ethereum \
  --name approve \
  --token 0xTOKEN_ADDRESS \
  --spender 0xSPENDER_ADDRESS \
  --amount 1000000 \
  --wallet WALLET \
  --index 0
```

Review the token, spender, allowance amount, network, wallet, and account index before running this command. Use the provider's documented chain-specific lookup, such as Velora's [`swap.getSpender()`](https://github.com/VeloraDEX/sdk/blob/86679ae70686ad3f01ee29baba9033be0a1b742b/src/methods/swap/spender.ts#L33-L63), when it supplies the approval target. Do not guess the spender, copy it from another chain, or infer it from a transaction recipient. Approve only the amount required in base units; avoid unlimited allowances unless the user explicitly requires and understands them.

The EVM `approve` method returns a transaction result containing a hash. Wait for that exact approval with the same wallet and account, require both `finality: confirmed` and `success: true` in the receipt, then call `getAllowance` again:

```bash title="Terminal"
wdk get transaction \
  --network ethereum \
  --hash APPROVAL_TRANSACTION_HASH \
  --finality confirmed \
  --wallet WALLET \
  --index 0
```

On Ethereum mainnet, the beta.5 EVM wallet rejects changing a nonzero USD₮ allowance directly to another nonzero value. When that exact case applies, approve `0`, verify a confirmed receipt with `success: true`, and verify the zero allowance before submitting the new bounded approval.

## Use JSON Output

```bash title="Terminal"
wdk --json method list --network spark
wdk --json method call --network spark --name getStaticDepositAddress
```

A successful call returns the network, method name, and result. Unknown methods, unknown parameters, missing required parameters, and malformed values return structured CLI errors. Do not retry by guessing method names or parameter shapes; list the catalog again.

## Use The Same Surface Over MCP

The bundled MCP server exposes `list_methods` and `call_method`. MCP arguments use the declared camel-case keys inside an `args` object rather than CLI-style kebab-case flags.

`call_method` has the same unlocked-wallet and write-method risks as the CLI command. See [Use the MCP Server](/cli/guides/use-mcp-server#call-module-methods) for the confirmation boundary.
