WDK CLI resolves token names such as `usdt` through a local registry. Each entry defines how the CLI formats amounts, selects a native or contract transfer, and connects the token to Indexer, fiat, and pricing providers.

Use this guide to [inspect the registry](#inspect-the-registry), [add a custom token](#add-a-custom-token), [override a built-in entry](#override-a-built-in-entry), or [enable and disable tokens](#enable-or-disable-a-token).

The effective registry combines built-in entries with your custom entries. A custom entry with the same network and token key replaces the built-in entry until you remove the override.

## Inspect The Registry

List tokens across enabled networks:

```bash title="Terminal"
wdk token list
```

Filter the list to one network or inspect one entry:

```bash title="Terminal"
wdk token list --network ethereum
wdk token info --network ethereum --token usdt
```

Use the lowercase registry key shown by these commands with `--token` on `get balance`, `send`, `buy`, and `sell`.

`get history --token` is different: pass the string at `metadata.slugs.indexer`, or its `slug` field when the mapping is an object. This code may differ from the registry key. See [history lookup](/cli/configuration#read-transfer-history).

## Token Spec

`wdk token add <data>` accepts either an inline JSON object or the path to a JSON file.

| Field | Required | Rules and effect |
| --- | --- | --- |
| `network` | Yes | Must name an existing built-in or custom network. |
| `token` | Yes | Registry key. Use lowercase letters, numbers, and hyphens; the first character must be a letter or number. |
| `symbol` | Yes | Non-empty display symbol, such as `WETH`. |
| `decimals` | Yes | Integer from `0` through `24`; used to convert decimal amounts to base units. |
| `isNative` | Yes | `true` uses the network's native transfer path; `false` uses a token contract or mint. |
| `address` | For non-native tokens | Non-empty contract or mint address. Optional for a native token. |
| `metadata` | No | Object containing supported provider mappings. |

A network can have at most one effective entry with `isNative: true`.

### Provider Metadata

| Field | Used by | Effect when omitted |
| --- | --- | --- |
| `metadata.slugs.indexer` | `wdk get history` | Pass its slug to `--token`. Without it, token-specific history cannot use the token and all-token history skips it. The network also needs its own `indexerSlug`. |
| `metadata.slugs.PROVIDER` | `wdk buy` and `wdk sell` | The selected fiat provider does not support that token through this registry. Examples of provider names are `moonpay` and `transak`. |
| `metadata.slugs.bitfinex` | USD price conversion with the bundled feed | The pricing client tries the token's display symbol instead. A missing price can leave balance output without a USD estimate. |

New token registrations accept only `slugs` inside `metadata`. Each system mapping must be a non-empty string or an object containing a non-empty `slug`; other object fields carry provider-specific inputs, such as Transak's `network`.

Stored custom entries using `indexerSlug`, `moonpaySlug`, or `bitfinexSlug` are normalized when loaded, and an explicit `metadata.slugs` entry wins. New `token add` requests with those legacy fields are rejected. Inspect an existing provider mapping with [`wdk token info`](/cli/api-reference#wdk-token-info) before recreating it.

Use [`wdk config set`](/cli/api-reference#wdk-config-set) with `overrides.tokens.NETWORK/TOKEN.metadata.slugs.PROVIDER` to add a mapping without replacing the complete token entry. The registry ignores overrides without a usable slug. Each provider mapping is merged separately, preserving mappings for other providers.

## Add A Custom Token

Create a file named `weth-on-ethereum.json`:

```json title="weth-on-ethereum.json"
{
  "network": "ethereum",
  "token": "weth",
  "symbol": "WETH",
  "decimals": 18,
  "isNative": false,
  "address": "0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2"
}
```

Add the entry:

```bash title="Terminal"
wdk token add ./weth-on-ethereum.json
```

You can also pass the JSON inline:

```bash title="Terminal"
wdk token add '{"network":"ethereum","token":"weth","symbol":"WETH","decimals":18,"isNative":false,"address":"0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2"}'
```

Verify the stored entry:

```bash title="Terminal"
wdk token info --network ethereum --token weth
```

`wdk token add` cannot retain a `nativeId`. A custom or overriding native entry is routable only when the selected protocol discovers it by symbol or does not require the native route identifier, so a custom native token is not guaranteed to swap or bridge.

<Callout type="info">
Adding a registry entry does not transfer tokens or interact with the blockchain. Verify contract addresses, decimals, and provider identifiers independently before using the entry to query or send assets.
</Callout>

## Understand Mutation Confirmation

`token add` and `token delete` protect registry changes with passphrase confirmation:

- If at least one wallet exists, the CLI prompts for the current default wallet's passphrase.
- If no wallet exists, the registry command does not prompt for a passphrase.
- Confirmation does not unlock, extend, or lock an existing daemon wallet session.

Set a valid default wallet before changing the registry if wallets already exist.

## Override A Built-In Entry

Adding a custom entry with the same `network` and `token` as a built-in entry replaces the complete effective entry; it does not merge individual fields. The CLI reports that the custom entry overrides the built-in entry.

Use overrides carefully. An incorrect address, decimal count, or native-token flag can route later balance or send operations incorrectly.

Remove the custom override to restore the built-in entry:

```bash title="Terminal"
wdk token delete --network ethereum --token usdt
```

## Enable Or Disable A Token

Disable a built-in or custom registry entry without deleting it using [`wdk token disable`](/cli/api-reference#wdk-token-disable). A network's native token cannot be disabled; disable the network instead.

For a non-native token:

```bash title="Disable a token entry"
wdk token disable --network ethereum --token usdt
```

Re-enable the entry before using it again:

```bash title="Enable a token entry"
wdk token enable --network ethereum --token usdt
```

The network must be enabled. Both commands verify the default wallet passphrase when a wallet exists and lock a running daemon; unlock again to apply the change. Directly disabled tokens remain listed with their status. The all-network listing omits tokens on disabled networks, and `wdk token list --network NETWORK` fails with `NETWORK_NOT_SUPPORTED` when that network is disabled.

## Delete A Custom Entry

Delete the WETH entry created above:

```bash title="Terminal"
wdk token delete --network ethereum --token weth
```

`token delete` removes only custom entries. It rejects deletion of a built-in entry when no custom override exists. Deleting a custom network also removes every custom token stored under that network.

`wdk config reset --all` preserves custom token entries.
