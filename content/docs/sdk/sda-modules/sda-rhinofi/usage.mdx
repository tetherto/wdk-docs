## Install and Configure

Before starting, obtain a Rhino.fi project `SECRET_` API key with SDA access. This server-side guide includes history and pause operations that require it. Prepare an EVM depositor address on Arbitrum and a destination address on Ethereum that you control or have independently verified. The example checks live support before using that pair.

Install the SDA package for the accountless flow:

```bash
npm install @rhino.fi/wdk-protocol-sda-rhinofi@1.0.1
```

Create an accountless [`RhinofiProtocol`](/sdk/sda-modules/sda-rhinofi/api-reference#rhinofiprotocol) and load the confirmed addresses from your server environment:

```javascript
import RhinofiProtocol, {
  RhinofiProtocolError,
  SdaExecutionError
} from '@rhino.fi/wdk-protocol-sda-rhinofi'

const apiKey = process.env.RHINO_API_KEY
if (!apiKey) throw new Error('Set RHINO_API_KEY')

function confirmedEvmAddress(name) {
  const address = process.env[name]
  if (!address || !/^0x[0-9a-fA-F]{40}$/.test(address) || /^0x0{40}$/i.test(address)) {
    throw new Error(`Set ${name} to a confirmed EVM address`)
  }
  return address
}

const depositor = confirmedEvmAddress('RHINO_DEPOSITOR_ADDRESS')
const destinationAddress = confirmedEvmAddress('RHINO_DESTINATION_ADDRESS')
const sourceChain = 'ARBITRUM'
const destinationChain = 'ETHEREUM'
const sda = new RhinofiProtocol(undefined, { apiKey })
```

Address syntax does not establish ownership or the intended chain. Confirm both addresses before continuing. Keep secret keys on your server; see [API Access](/sdk/sda-modules/sda-rhinofi/configuration#api-access).

For TypeScript, import option and result types separately from the JavaScript classes and errors:

```typescript
import type {
  RhinofiCreateDepositAddressOptions,
  RhinofiQuoteDepositOptions,
  RhinofiSdaDepositAddress,
  RhinofiSdaTransfer
} from '@rhino.fi/wdk-protocol-sda-rhinofi'
```

## Discover a Route

Use [`getSupportedRoutes()`](/sdk/sda-modules/sda-rhinofi/api-reference#getsupportedroutes) to check whether USD₮0 is accepted on Arbitrum and USD₮ is delivered on Ethereum:

```javascript
const routes = await sda.getSupportedRoutes({
  sourceChain,
  sourceToken: 'USDT',
  destinationChain,
  outputAsset: 'USDT'
})
const route = routes[0]
const inputToken = route?.inputTokens.find(token => token.token === 'USDT')
if (!route || !inputToken) throw new Error('The requested deposit route is unavailable')

console.log(inputToken.decimals)
console.log(inputToken.minDepositLimitUsd, inputToken.maxDepositLimitUsd)
```

For this pair, Rhino.fi uses the machine identifier `USDT` for USD₮0 on Arbitrum and USD₮ on Ethereum. Preserve that provider identifier in calls. Use the returned token identifier and decimals together. Deposit bounds are USD values, not token base units. Refresh discovery when presenting a route; an earlier response does not reserve it. Passing `sourceChain` avoids querying every deposit-enabled source chain.

## Estimate a Deposit (optional)

Use [`quoteDeposit()`](/sdk/sda-modules/sda-rhinofi/api-reference#quotedeposit) to estimate the output and fees for 100 USD₮0, expressed using the discovered source-token decimals:

```javascript
const inputAmount = 100n * 10n ** BigInt(inputToken.decimals)
const quote = await sda.quoteDeposit({
  sourceChain,
  inputToken: inputToken.token,
  destinationChain,
  outputAsset: 'USDT',
  inputAmount,
  depositor,
  destinationAddress
})

console.log(quote.outputAmount, quote.fees)
```

The amount must fit the provider's current USD deposit limits. Both addresses are required even for a protocol bound to an account. The provider prices the actual deposit when funds arrive; this estimate contains no reusable quote ID or expiry and does not cap later fees or guarantee this output amount.

## Create a Deposit Address

1. Confirm the destination chain and address, accepted token, USD limits, and indicative fees with the user.
2. Request the address using [`createDepositAddress()`](/sdk/sda-modules/sda-rhinofi/api-reference#createdepositaddress).
3. Store the returned descriptor and the confirmed destination together before showing funding instructions.

<Callout type="warn">
The following call creates or reuses a live provider deposit address. It does not transfer funds. Only fund it with a token and source chain accepted by its current descriptor. The depositor's ordinary wallet transfer is a separate action outside this module.
</Callout>

Request an address using the same confirmed destination as the estimate:

```javascript
const deposits = await sda.createDepositAddress({
  sourceChains: [sourceChain],
  destinationChain,
  outputAsset: 'USDT',
  destinationAddress,
  reusePolicy: 'reuse-existing'
})
const deposit = deposits.find(item => item.sourceChains.includes(sourceChain))
if (!deposit) throw new Error('No deposit address returned for the selected chain')
if (deposit.isActive !== true || deposit.isPaused !== false) {
  throw new Error('Deposit address is inactive, paused, or has incomplete lifecycle data')
}
const acceptedToken = deposit.supportedInputTokens.find(token => token.token === inputToken.token)
if (!acceptedToken) throw new Error('The address does not currently accept the selected token')

console.log(deposit.address, deposit.id, acceptedToken)
console.log(acceptedToken.minDepositLimitUsd, acceptedToken.maxDepositLimitUsd)
```

Use the created descriptor's token and USD limits in the funding instructions, and refresh the descriptor before a later deposit. Keep `deposit.id` verbatim for lookups and lifecycle actions. With a standard API key, `deposit.destinationAddress` is omitted even though the requested destination controls settlement. See [Address Creation Options](/sdk/sda-modules/sda-rhinofi/configuration#address-creation-options) for labels, webhooks, refunds, and asset fallback.

For a Stellar descriptor containing `chainMetadata`, a sender that cannot use the muxed address must send to `baseAddress` with the exact `memoId`. Omitting the memo prevents deposit attribution. Read these values from the descriptor rather than constructing them.

## Track Deposits

Configure a project webhook in the Rhino.fi Console, or pass an approved `webhookUrl` when creating an address. Verify events using the provider's [signature-verification instructions](https://docs.rhino.fi/webhook/verify-webhook-signature) before trusting their contents. The SDA module exposes history methods for reconciliation; it does not verify or receive webhook events.

Use [`getTransfers()`](/sdk/sda-modules/sda-rhinofi/api-reference#gettransfers) to read the last 31 days for the address on its source chain:

```javascript
const transfers = await sda.getTransfers(deposit.address, {
  sourceChain,
  limit: 20,
  skip: 0
})
for (const transfer of transfers) {
  console.log(transfer.id, transfer.status, transfer.txHash)
}
```

For an older period, pass valid `fromTimestamp` and `toTimestamp` dates spanning no more than 31 days. Filtering and pagination apply within the fetched window; increasing `skip` does not fetch older periods.

Use [`getTransfer()`](/sdk/sda-modules/sda-rhinofi/api-reference#gettransfer) with an identifier returned by history:

```javascript
if (transfers.length > 0) {
  const transfer = await sda.getTransfer(transfers[0].id)
  console.log(transfer.status)
}
```

`getTransfer()` searches address history within the same default window. Supply the original window when looking up an older transfer. A missing result can mean the transfer is outside the window.

Interpret each transfer independently. Rejected deposits report `refund-pending`, and polling does not change that status to `refunded`. Use the provider's [`SDA_REFUND_COMPLETED` event](https://docs.rhino.fi/webhook/events-list) for refund completion. Unsupported or out-of-range deposits can require the provider's Account Management team to arrange recovery; do not assume every rejected transfer is automatically refunded. Unknown provider states map to `processing`; see [Transfer Status](/sdk/sda-modules/sda-rhinofi/api-reference#transfer-status).

## Pause or Resume an Address

Use [`disableDepositAddress()`](/sdk/sda-modules/sda-rhinofi/api-reference#disabledepositaddress) to pause acceptance for the address and chain identified by `deposit.id`:

```javascript
await sda.disableDepositAddress(deposit.id)
```

Deposits arriving during the pause are rejected. Refund handling can require provider intervention. Pausing does not establish that an existing transfer has completed or that its refund was issued.

Use [`enableDepositAddress()`](/sdk/sda-modules/sda-rhinofi/api-reference#enabledepositaddress) to resume acceptance:

```javascript
await sda.enableDepositAddress(deposit.id)
```

## Register with WDK (optional)

Use this alternative when your application already manages the destination account through WDK. Install all three packages imported by the account-bound example:

```bash
npm install @rhino.fi/wdk-protocol-sda-rhinofi@1.0.1 @tetherto/wdk@1.0.0-beta.18 @tetherto/wdk-wallet-evm@1.0.0-beta.20
```

1. Register the destination wallet and the SDA protocol with [`registerProtocol()`](/sdk/core-module/api-reference#registerprotocolblockchain-label-protocol-config).
2. Retrieve the destination account and its SDA protocol.
3. Dispose the WDK wallet after using it.

Retrieve the registered provider with [`getSdaProtocol()`](/sdk/core-module/api-reference#getsdaprotocollabel); the example only reads the account's address:

```javascript
import WDK from '@tetherto/wdk'
import WalletManagerEvm from '@tetherto/wdk-wallet-evm'
import RhinofiProtocol from '@rhino.fi/wdk-protocol-sda-rhinofi'

const seed = process.env.WDK_SEED_PHRASE
const apiKey = process.env.RHINO_API_KEY
if (!seed || !WDK.isValidSeed(seed) || !apiKey) {
  throw new Error('Set a valid WDK_SEED_PHRASE and RHINO_API_KEY')
}

const wdk = new WDK(seed)
try {
  wdk.registerWallet('ethereum', WalletManagerEvm, {})
  wdk.registerProtocol('ethereum', 'rhinofi-sda', RhinofiProtocol, { apiKey })
  const account = await wdk.getAccount('ethereum', 0)
  const accountSda = account.getSdaProtocol('rhinofi-sda')
  const destinationAddress = await account.getAddress()
  console.log(destinationAddress, typeof accountSda.createDepositAddress)
} finally {
  wdk.dispose()
}
```

The bound account supplies the default creation destination when omitted. Always pass `destinationChain` explicitly and match it to that account. The returned core interface is `ISdaProtocol`. The JavaScript registration flow works with the package combination above, but current `1.0.1` declarations have [TypeScript compatibility limitations](/sdk/sda-modules/sda-rhinofi/api-reference#typescript-compatibility). Use a direct [`RhinofiProtocol`](/sdk/sda-modules/sda-rhinofi/api-reference#rhinofiprotocol) instance when you need provider-specific TypeScript options, return fields, or [`enableDepositAddress()`](/sdk/sda-modules/sda-rhinofi/api-reference#enabledepositaddress).

## Handle Errors

Use the imported [`SdaExecutionError`](/sdk/sda-modules/sda-rhinofi/api-reference#errors) and [`RhinofiProtocolError`](/sdk/sda-modules/sda-rhinofi/api-reference#errors) classes to classify provider failures:

```javascript
try {
  await sda.getDepositAddress(deposit.id)
} catch (error) {
  if (error instanceof SdaExecutionError) {
    console.error('Rhino.fi request failed', error.code)
  } else if (error instanceof RhinofiProtocolError) {
    console.error(error.name)
  } else {
    throw error
  }
}
```

`SdaExecutionError.code` is optional. Local numeric conversions can also throw native errors. Validate caller inputs and avoid logging credentials or unfiltered provider error details. After an uncertain address-creation response, reconcile with your stored provider records before requesting another address.
