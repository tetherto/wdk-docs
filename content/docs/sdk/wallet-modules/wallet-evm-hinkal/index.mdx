Use [`@hinkal/wdk-wallet-evm-hinkal`](https://www.npmjs.com/package/@hinkal/wdk-wallet-evm-hinkal) to add Hinkal private sends to a WDK EVM account. The module deposits funds on chain and schedules a later withdrawal to the recipient. It also exposes scheduled-send status and recovery of stuck shielded balances.

[Hinkal](https://github.com/Hinkal-Protocol/wdk-wallet-evm-hinkal) maintains this module. These pages describe **v0.0.7**, which uses `@tetherto/wdk-wallet-evm@1.0.0-beta.18` and `@hinkal/common@0.3.13`.

## Choose This Module

Use Hinkal when your application needs private sends from a **seed-derived EVM account**, can track asynchronous settlement, and can reconcile interrupted deposits and recovery operations.

For ordinary EVM transfers, use [Wallet EVM](/sdk/wallet-modules/wallet-evm). Hinkal account creation does not accept hardware signers, private-key signers, or named signers. Address-only accounts cannot query Hinkal shielded balances or scheduled-send status through this module.

## Account Capabilities

| Task | Method |
|---|---|
| Deposit tokens and schedule a private withdrawal | [`privateSend()`](/sdk/wallet-modules/wallet-evm-hinkal/api-reference#privatesend) |
| Read scheduled withdrawal status | [`getSendStatus()`](/sdk/wallet-modules/wallet-evm-hinkal/api-reference#getsendstatus) |
| Find stuck shielded balances | [`stuckUtxoBalances()`](/sdk/wallet-modules/wallet-evm-hinkal/api-reference#stuckutxobalances) |
| Recover a token to the account's own address | [`withdrawStuckUtxos()`](/sdk/wallet-modules/wallet-evm-hinkal/api-reference#withdrawstuckutxos) |

Accounts retain the [inherited EVM operations](/sdk/wallet-modules/wallet-evm-hinkal/api-reference#inherited-evm-apis), including ordinary balances, transfers, signing, and transaction tracking. Those operations do not become private sends.

## Integration Requirements

- A BIP-39 mnemonic or seed bytes, handled by the host application's secret storage.
- An RPC provider on the selected chain, plus a token supported by Hinkal on that chain. An EVM RPC alone does not establish Hinkal support. Consult the [Hinkal documentation](https://hinkal-team.gitbook.io/hinkal) and check current provider support before enabling a route.
- A runtime that resolves the Hinkal dependency correctly. Node applications need the [bundling setup](/sdk/wallet-modules/wallet-evm-hinkal/usage#build-for-node); v0.0.7 does not load directly as native Node ESM. The package also supplies a Bare conditional entrypoint.
- Application handling for deposits, scheduled withdrawals, approvals, fees, and interrupted operations. There is no private-send quote or maximum-fee option in this module.
