Use middleware to inspect, decorate, or replace a wallet account as WDK retrieves it.

## Register Middleware

Register middleware for the identifier you passed to [`registerWallet()`](/sdk/core-module/api-reference#registerwalletblockchain-wallet-config). WDK attaches the account's protocol methods first, then calls your callbacks in registration order on every [indexed](/sdk/core-module/api-reference#getaccountblockchain-index) or [path-based](/sdk/core-module/api-reference#getaccountbypathblockchain-path) retrieval, including cached accounts.

The second argument is [`MiddlewareContext`](/sdk/core-module/api-reference#middleware-function). It contains the wallet identifier, the original account's captured full path, and the index if you retrieved the account by index. All callbacks on that retrieval receive the same context. The context path comes from the wallet account, so a relative input to `getAccountByPath()` is not echoed as the full path.

Return nothing to keep the current account. A non-nullish result replaces it for the next callback and the caller. When returning a replacement, preserve the wallet methods and protocol getters that the caller needs. If your callback only calls a helper, use a block with no return value so a result from that helper cannot replace the account.

### Logging

```javascript title="Logging Middleware"
wdk.registerMiddleware('ethereum', async (account, { blockchain, index }) => {
  console.log('Accessed account:', blockchain, index, await account.getAddress())
})
```

Register middleware that adds or wraps account methods **before** [attaching Policies](/sdk/core-module/guides/transaction-policies#register-policies). Later middleware receives the governed account when a policy applies. That account rejects function, accessor, and prototype changes. See [policy method customization](/sdk/core-module/guides/transaction-policies#customize-before-retrieval).

## Use provider failover

Provider failover is handled outside core middleware. Use the current [`@tetherto/wdk-failover-provider`](https://www.npmjs.com/package/@tetherto/wdk-failover-provider) package when you need provider-level retry and fallback across RPC endpoints.

Install the failover provider package:

```bash
npm install @tetherto/wdk-failover-provider
```

Import the provider in your wallet or infrastructure setup:

```typescript
import FailoverProvider from '@tetherto/wdk-failover-provider'
```

Use this when your app depends on external RPC providers and needs a backup route if the primary provider is slow or unavailable.

See [Add provider failover](/tools/failover-provider/), [failover configuration](/tools/failover-provider/configuration/), and the [failover API reference](/tools/failover-provider/api-reference/) for the supported setup.
